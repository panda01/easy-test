# server/prisma/

Prisma 7 schema for the PostgreSQL database.

## The one rule

**Never import from `../generated/prisma/` in application code.** Go through
`../services/dbService.ts`, which owns the single `PrismaClient` and exposes
named query functions. The generated directory is gitignored and is rewritten
on every `prisma generate`.

## Two Prisma 7 specifics worth knowing

1. **The connection URL is not in this schema.** The `datasource db` block
   carries only `provider = "postgresql"`. The URL comes from the project-root
   `prisma.config.ts`, which imports `server/bootEnv.js` first because Prisma 7
   loads its config file with dotenv disabled. This is what `prisma init`
   generates on Prisma 7.
2. **A driver adapter is mandatory.** `PrismaClientOptions` types `adapter` as
   required unless you pass `accelerateUrl`, so plain `new PrismaClient()`
   neither typechecks nor runs. `dbService.ts` constructs a `PrismaPg`.

The generator is `prisma-client` (the ESM generator), **not** the legacy
`prisma-client-js`. It emits TypeScript sources rather than writing into
`node_modules`.

## Models

| Model | Table | Purpose |
|---|---|---|
| `Website` | `websites` | A website a user wants to test: url, name, optional description, and two screenshot timing settings — `networkIdleTimeoutMs` (default 5000) and `screenshotMinimumWaitMs` (default 1) — and `loginUrl` (null = doesn't require login; credentials inherit it; learned from the first successful login with a credential's own URL via `adoptWebsiteLoginUrl`, never overwriting one already set). |
| `UseCase` | `use_cases` | A scenario to test on one website: title, description (both required). |
| `Action` | `actions` | A reusable step on one website, e.g. "Log in": title, description (both required), and an optional `credentialId` - the credential it logs in as before each run (null = runs logged out; deleting the credential unlinks it). |
| `ScreenshotRun` | `screenshot_runs` | One visit the Playwright controller made to a website: the URL visited, whether it succeeded, the HTTP status, the failure reason, the screenshot's file name, and how long navigation took. |
| `ActionScript` | `action_scripts` | One JSON step plan version of an action - generated by Claude or saved from the step editor: snapshots of what was sent (website name and URL, action title and description, `credentialId` / `credentialName`), the summary, `assumptions String[]`, the `plan Json` (`{ name, startUrl, steps }` - data, never code), `contextPageUrls String[]` (the crawled pages Claude was shown), the `modelId` that answered and the `effort` level sent (both null on an edited version), and `editedFromActionScriptId` (the version an edit was saved from; null when generated or refined). A **refined** version has a `modelId` and a `refinement` (the `ActionScriptRefinement` that produced it); `refinementsOfThisVersion` lists the refinements made from it. **Immutable** - create-only. |
| `ActionScriptRun` | `action_script_runs` | One run of a plan: `succeeded`, `timedOut`, `errorMessage` and `failedStepNumber` (where and why it stopped; null when it passed), `credentialName` (who it logged in as), the capped `output` (step log, never typed text) and `outputWasTruncated`, the failure screenshot's file name, `failingPageUrl` and `failingPageAriaSnapshot` (where the browser was and what the page held when it failed - scrubbed, the snapshot capped; null when it passed or for older runs), and the duration. Create-only. |
| `ActionScriptRefinement` | `action_script_refinements` | One "Refine" of a failed run: the LINK between `sourceActionScriptId` (the version that failed), `actionScriptRunId` (its failed run), and `refinedActionScriptId` (the new version Claude wrote; unique). It stores only what exists nowhere else: the user's `note`, the refine call's token usage (`inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`), and `screenshotWasSent`. The error and failed step stay on the run, the model and effort on the refined version (one source of truth). Written only when the refine succeeded, in the same write as the new version. Create-only. |
| `CrawlRun` | `crawl_runs` | One background crawl of a website: `startUrl` (snapshot), `status` (`running`, `finished`, `stoppedAtPageLimit`, `stoppedAtTimeLimit`, `failed`, `interrupted`), `pageLimit`, the live counters `visitedPageCount` / `waitingUrlCount`, `errorMessage`, and `durationMs` / `finishedAt` (null while running). `credentialId` is the credential it logs in as (null = logged out); `isLoggedIn` turns true once that login worked, **before** the first page is recorded - so it holds for every page of the run. A failed login ends the run `failed` with no pages, and `loginFailureScreenshotFileName` (relative to `SCREENSHOT_DIR`, like `ScreenshotRun.screenshotFileName`) names the PNG of what the browser showed. `buttonMode` (`linksOnly` default, `allButRisky`, `openOnly`) is which buttons the crawl clicked. |
| `Credential` | `credentials` | A login for one website: `name`, optional `description`, `username`, `encryptedPassword` (AES-256-GCM with `CREDENTIAL_ENCRYPTION_KEY`, `iv.authTag.ciphertext` - **never** plain text, never sent by the API), `loginUrl` (optional override - null inherits the website's), and optional CSS selectors `usernameSelector` / `passwordSelector` / `submitSelector` that replace the crawler's own guess. |
| `CrawledPage` | `crawled_pages` | One page a crawl visited: `parentPageId` (self-relation - the page whose link first led here; null for the start page), `url` (identity: origin + path - where the browser LANDED; the requested page instead when the landing page is already recorded in the run), `requestedUrl`, `finalUrl`, `wasRedirected` (landed on a different origin + path than requested), `visitOrder`, `depth`, `succeeded`, `httpStatus`, `errorMessage`, `title`, the YAML `ariaSnapshot`, `linkedUrls String[]` (same-origin links on the page), and the duration. Create-only. `buttonUrls String[]` lists the same-site pages its buttons led to, and `foundByButtonText` names the button whose click first led to this page (null when a link did). |

`UseCase`, `Action`, and `ScreenshotRun` each belong to exactly one `Website`
(`websiteId`, indexed). `ActionScript` belongs to one `Action` and, denormalized
for single-statement cascades, its `Website`; `ActionScriptRun` carries all
three parent ids (`websiteId`, `actionId`, `actionScriptId`, each indexed).
`ActionScriptRefinement` carries `websiteId` and `actionId` (indexed, for the
cascades) and points at two `ActionScript`s through the named relations
`RefinementSourceScript` (indexed) and `RefinementResultScript` (unique), and
at the failed `ActionScriptRun` (indexed).
`CrawlRun` belongs to one `Website` and optionally points at the `Credential`
it logged in as (`credentialId`, indexed); an `Action` likewise optionally
points at the `Credential` it runs as (`credentialId`, indexed); `CrawledPage` belongs to one
`CrawlRun` and, denormalized, its `Website`. `Credential` belongs to one
`Website`. The foreign keys use Prisma's default
`onDelete: Restrict`, which is fine because rows are never hard deleted.

The pages of one crawl form a **tree** through the `CrawledPageTree`
self-relation (`parentPage` / `childPages`, `parentPageId` indexed; Prisma's
default for an optional relation makes it `ON DELETE SET NULL`). `linkedUrls`
keeps the full link graph alongside the tree. `(crawlRunId, url)` is unique,
so a crawl never records the same page twice.

`ScreenshotRun.screenshotFileName` is **relative** to the configured
screenshot directory (`SCREENSHOT_DIR`), e.g. `<websiteId>/<uuid>.png`, and is
null when the visit never reached a page. The PNG itself lives on disk, not in
the database. `requestedUrl` is a snapshot, because the website's URL can be
edited after the run.

`ActionScriptRun.failureScreenshotFileName` is likewise **relative** to
`ACTION_SCRIPT_DIR`, e.g. `<websiteId>/<uuid>/failure.png`. Converting an
action again, saving an edited plan, or refining a failed run never edits a
version - it adds a new row, which the UI shows as the next "Version N".

Fields are camelCase and are **not** individually `@map`'d — only table names
are mapped. Postgres therefore stores quoted mixed-case columns, so
hand-written SQL must quote them:

```sql
select "createdAt" from websites;   -- works
select createdAt from websites;     -- fails
```

## Soft delete

All ten models have a nullable `deletedAt`. Deleting sets it instead of
removing the row, and every `dbService` query filters `deletedAt: null`.
Deleting a website also stamps its active use cases, actions, screenshot
runs, action scripts, action script runs, action script refinements, crawl
runs, crawled pages, and credentials, in
one transaction, with the **same** timestamp — so that batch can be identified together later. Deleting
an action likewise stamps its active scripts, their runs, and their
refinements with the action's timestamp. A soft-deleted run's PNG (and run folder) stays on disk. Scripts
and runs are never deleted on their own.

## The partial unique index on `Website.url`

```prisma
@@unique([url], where: { deletedAt: null })
```

A URL may appear on any number of soft-deleted websites but on at most one
active website, so a deleted website's URL can be added again. This needs the
**`partialIndexes` preview feature** (enabled in the generator block). In
Postgres it is `websites_url_key ... WHERE "deletedAt" IS NULL`.

Prisma still lists `url` in `WebsiteWhereUniqueInput`, but because several
deleted rows can share a URL, URL lookups use `findFirst` with
`deletedAt: null`, never `findUnique`.

URLs are normalized with `new URL(input).href` before they are stored (see
`../utils/validateRequestBodies.ts`), so `HTTPS://Example.COM` and
`https://example.com/` collide on this index instead of becoming two websites.

## Workflow

Migrations are not used — this project is `db push` only. After any schema
change:

```sh
npx prisma db push
npx prisma generate
```

`npm install` runs both automatically via `postinstall`. A change that adds a
unique index makes `db push` ask for `--accept-data-loss`, because the index
cannot be created if duplicates exist.
