# src/components/

Reusable building blocks for pages. Components take props and render; any
fetching is done by the page through a hook and passed down.

| Component | Does |
|---|---|
| `icons.tsx` | Every icon the app draws, and the only module that imports `@mui/icons-material` - one path import per icon (`@mui/icons-material/Add`), so the bundle never carries the whole library. Also `NotRunIcon`, a dashed circle made with MUI's `createSvgIcon`. Components import icons from here. |
| `AppHeader.tsx` | Top bar on every page: the Easy Test mark and name (links to the dashboard) and a "Websites" link (`aria-current` while on the dashboard). Rendered outside `<Routes>`. |
| `PageBreadcrumbs.tsx` | The "Websites / Example / Log in" trail; the last crumb is plain text. Below 900 px it collapses to one "‹ Parent" back link (the last crumb that links somewhere). |
| `PageContainer.tsx` | The frame of each redesigned screen: 28 px gutters on desktop, 18 px on a phone, an optional `maxWidth`. A frame capped by `maxWidth` (the dashboard's 1080 px) is centered in the window; an uncapped one fills it. |
| `LoadStatusNotice.tsx` | Spinner while loading, error alert on failure, nothing once loaded. |
| `ConfirmDeleteDialog.tsx` | Confirm-before-delete dialog that also shows a failed delete's reason. |
| `MoreActionsMenu.tsx` | The phone layout's 44 px "⋯" ("More actions") button with Edit (a link) and Delete, used by the website and action pages. |
| `StatusDot.tsx` | The small decorative status dot (optionally glowing, for a running crawl, or hollow); `aria-hidden`, since the text beside it says the same. |
| `StatusTag.tsx` | A small tinted label (`stale` "Out of date", `loggedIn`, `failed`, `accent`, `neutral`), Nocturne's `.tag`, on an MUI `Chip`. |
| `ActionStatusBar.tsx` | A website's actions at a glance: a thin passed / failed / not run bar (`aria-hidden`) and the counts in words, with dots on desktop. |
| `DisclosureRow.tsx` | A collapsed "› Label · detail" row (`aria-expanded`) whose content is mounted only while open: Assumptions, Pages given to Claude, Plan JSON, Output log, Run history. |
| `CrawlProgressCard.tsx` | A running crawl in an accent card (`role="status"`): glowing dot, title, ticking elapsed time, progress bar of pages against the limit, "12 of up to 50 pages · 8 waiting", optional "Watch" link. |
| `WebsiteForm.tsx` | URL / name / description / optional login page URL (blank = the website doesn't require login) form for the website create and edit pages, plus the "Screenshot settings" number fields (network idle cap and minimum wait, in ms). |
| `TitleDescriptionForm.tsx` | Title / description form for the use case and action create and edit pages. Given `credentialOptions` (actions only) it adds a "Log in as" select - logged out (`LOGGED_OUT_CREDENTIAL_VALUE`) or one of the website's credentials - and submits it as `credentialId`. |
| `CredentialForm.tsx` | Name / description / login page URL / username / password form for the credential create and edit pages, plus the optional "Login form selectors". On edit (`passwordIsSaved`) a blank password keeps the saved one. The login page URL is an optional override when the website has one (`websiteLoginUrl` is the placeholder; blank inherits it), and required when it has none. |
| `CredentialsSection.tsx` | The website page's "Credentials" tab: "New credential" and each credential (name, then username and description) linking to its edit page. Never shows a password. |
| `WebsiteItemListSection.tsx` | The website page's "Actions" or "Use cases" section. Actions: "4 passed · 2 failed · 1 not run", "New action", and one row per action linking to it - its `ScriptRunStatusIcon`, title with an "Out of date" tag (`findChangedActionFields` on `newestScript`), description, who it runs as, "vN", and its status label (`describeLatestRunLabel`). Use cases: "New use case" and the use cases as cards. On a phone (`isPhoneLayout`) the section sits in its own tab, so it has no heading, and action rows are compact. |
| `ScriptRunStatusIcon.tsx` | Whether a script version works, judged by its most recent run (`findScriptRunStatus`): a green outlined check when it passed, a red outlined X when it failed, a grey dashed circle (`NotRunIcon`) when it has no runs. Its accessible name and hover title are "Latest run passed", "Latest run failed", or "Not run yet" (`describeScriptRunStatus`). |
| `ScreenshotRunsSection.tsx` | The website page's "Screenshots" tab: "Take screenshot" (with progress and its error), a line explaining when screenshots are taken (the website's timing settings), the selected run (newest by default), and the "History" list to pick a run from. |
| `ScreenshotRunDetails.tsx` | One screenshot run in full: a `role="status"` outcome line ("Failed · HTTP 404 · 1.2 s") with its reason, when and where it was taken, and its image (or "No screenshot was captured"). |
| `WebsiteItemSummary.tsx` | The top of a use case's page: kind, title with Edit (link) and Delete, description, an optional `detailText` line, timestamps, and the delete dialog. The delete flow comes in as a `WebsiteItemDeletion` prop (`../hooks/useWebsiteItemDeletion.ts`). |
| `ActionScriptsSection.tsx` | The action page's versions column: "Versions" with "Compare" once there are two, one row per version (`ScriptRunStatusIcon` from its `latestRun`, "Version N", an "Out of date" tag, and where it came from - "Refined from v4 · Opus 5.5 · 24 min ago", "Edited from v3 · 1 h ago", or "Opus 5.5 · high · 2 h ago"), then the Model / Effort dropdowns (`ScriptModelPicker`) and "Convert to new version" with progress and its error. On a phone (`isPhoneLayout`) the list is a "Version" dropdown ("Version 5 · Failed · 24 min ago"). |
| `ActionScriptDetails.tsx` | The shown plan version: "Version N" with "Edit steps" (which swaps in `ActionPlanEditor`), where it came from and when, Claude's summary, the steps (`ActionPlanSteps`, marked by `highlightedRun`), and collapsed rows for Assumptions, Pages given to Claude, and Plan JSON. On a phone it is headed "Steps" without the caption and summary, and lists `leadingDisclosures` (the page's Run history and Output log) first. |
| `ActionPlanSteps.tsx` | A plan read-only: "Starts at <url>", then the numbered steps with the verb muted (`describePlanStepParts`); credential placeholders are named, never shown. Against `highlightedRun`: reached steps get green numbers, the failed step is tinted red with "Failed here — <the error's first line>" (desktop), later steps are dimmed. |
| `ActionPlanEditor.tsx` | The step editor: plan name and start URL, then the steps as cards in a dnd-kit `SortableContext` (drag a handle with the mouse or the keyboard - Space, arrows, Space), "Add step", a "Fix these before saving" list (`findPlanProblems`), and "Save as new version" (disabled until something changed and nothing is wrong) / Cancel. Steps get client-only ids for keys and dragging. |
| `ActionPlanStepFields.tsx` | One step card in the editor: drag handle, "Step N", the Action select, "Find element by" (role + name, label, placeholder, text, alt text, title, or CSS - plus "No element" for an optional target), the value field shaped by the action (key list, accept/dismiss, or text), and Move up / Move down / Delete. Only the fields the action takes are shown. |
| `ScriptModelPicker.tsx` | The compact "Model" and "Effort" dropdowns side by side (named for screen readers): every model in the live list and the chosen model's own effort levels (or a disabled "Standard"); the model's hover title names its id and fallback. Shows why the list could not load instead. |
| `SideBySideDiff.tsx` | One section of a side-by-side comparison (older text left, newer right): removed lines red, added lines green, changed words highlighted, filler keeping rows aligned, "No differences" when equal. Rows come from `../utils/buildSideBySideDiff.ts`. |
| `ActionScriptRunsSection.tsx` | The action page's run panel for the shown version: "Latest run" (or "Run" once an older run is picked) with "Run again" ("Run" before the first run; it opens a browser window on this computer, logging in as the action's credential first when it has one) and its progress and error, the shown run via `ActionScriptRunDetails` (keyed by the run's id, so the refine note and error start over per run), and "Runs of version N" (`ActionScriptRunHistory`). On a phone it is the card above the steps, with "Run again" beside Refine. |
| `ActionScriptRunDetails.tsx` | One plan run in full: a `role="status"` banner ("Failed at step 3", then the error, how long it took, and when), the failure screenshot and failing page URL, and for a failed run of a version Claude wrote (`versionCanBeRefined`) "Refine with Claude": a note (at most `MAX_REFINE_NOTE_LENGTH`, 2000 characters, with a counter; sent trimmed, blank as null) and "Refine into Version N" ("Refining…", with progress and "This can take a few minutes."), and "Could not refine: …" - shown only once this run's details tried to refine. Desktop adds the collapsed "Output log". |
| `ActionScriptRunHistory.tsx` | A version's runs as rows (dot, outcome, relative time) to pick the shown run from (`aria-current`). |
| `ActionScriptRunOutput.tsx` | A run's step log in a `CodeBlock` (with a note when its start was dropped), or "The run logged nothing."; also `countOutputLines` / `describeOutputLineCount` for the "Output log · 42 lines" row. |
| `CodeBlock.tsx` | A read-only, monospace, scrollable `<pre>` on Nocturne's dark code ground, with an accessible name. Also shows aria snapshots. |
| `CrawlRunsSection.tsx` | The website page's "Crawls" tab, as a column: the "Crawl as" picker (logged out, or one of the website's credentials - `CRAWL_LOGGED_OUT_VALUE` is the logged-out option; shown only when `crawlAsPickerIsShown`), the "Buttons" picker ("Links only (no buttons)" - `DEFAULT_CRAWL_BUTTON_MODE` -, "Buttons, except risky ones", "Only “Open” buttons"), each on its own line, then "Crawl website" below them (disabled while starting one or while one runs, with "One crawl at a time — …"), its error, the running crawl as a `CrawlProgressCard` with "Watch", and the "History" of the other crawls that match both picks (dot, `describeCrawlRunHistoryLabel`, relative time), each linking to its page - or a line saying none matches ("No crawls as “Admin” with links only yet."). |
| `CrawlSiteMap.tsx` | The "Site map" of a crawl: every page as one indented list in tree order (each page under the page whose link first led to it), with a green or red dot, its path, and a note (`describeSiteMapNote`: "HTTP 404", "from /", "→ /calendar", "via “Open Yoga”"); picking a row selects the page. A surface panel on desktop, 44 px rows on a phone. Built with `../utils/buildCrawlSiteTree.ts`. |
| `CrawledPageDetails.tsx` | One crawled page in full: its path, a row of facts (the HTTP status in green or red, title, `describeRedirectFact`, "Found on /" - a button, with "via “Open Yoga”" when a button led here - or "Start page"), a failed page's error, the "Links · N" and "Buttons led to · N" cards (visited entries select their page, the rest are marked "not visited"), and the aria snapshot with its line count. |

## Conventions

- One default-exported component per file, with an exported `<Name>Props`
  interface whose fields are documented. Props arrive as a single `props`
  parameter and are destructured in the body.
- Forms own only their field values. Saving, error text, and navigation come
  from the page via props (`onSubmit`, `errorMessage`, `onCancel`).
- Forms seed their fields from `initialValues` once, on mount. Pages that edit
  a loaded record mount the form only after it loads, with `key={record.id}`.
- Submit stays disabled until the required fields are non-blank; the server
  still validates and its message is shown in an alert.
