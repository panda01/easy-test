# src/components/

Reusable building blocks for pages. Components take props and render; any
fetching is done by the page through a hook and passed down.

| Component | Does |
|---|---|
| `AppHeader.tsx` | Top bar on every page: app name (home) and a Websites link. Rendered outside `<Routes>`. |
| `PageBreadcrumbs.tsx` | The "Websites › Example › Log in" trail; the last crumb is plain text. |
| `LoadStatusNotice.tsx` | Spinner while loading, error alert on failure, nothing once loaded. |
| `ConfirmDeleteDialog.tsx` | Confirm-before-delete dialog that also shows a failed delete's reason. |
| `WebsiteForm.tsx` | URL / name / description / optional login page URL (blank = the website doesn't require login) form for the website create and edit pages, plus the "Screenshot settings" number fields (network idle cap and minimum wait, in ms). |
| `TitleDescriptionForm.tsx` | Title / description form for the use case and action create and edit pages. Given `credentialOptions` (actions only) it adds a "Log in as" select - logged out (`LOGGED_OUT_CREDENTIAL_VALUE`) or one of the website's credentials - and submits it as `credentialId`. |
| `CredentialForm.tsx` | Name / description / login page URL / username / password form for the credential create and edit pages, plus the optional "Login form selectors". On edit (`passwordIsSaved`) a blank password keeps the saved one. The login page URL is an optional override when the website has one (`websiteLoginUrl` is the placeholder; blank inherits it), and required when it has none. |
| `CredentialsSection.tsx` | The "Credentials" section of a website's page: "New credential" and each credential (name, then username and description) linking to its edit page. Never shows a password. |
| `WebsiteItemListSection.tsx` | The "Use cases" or "Actions" section of a website's page. Each action has a `ScriptRunStatusIcon` before its title, judged by its newest version's latest run (`newestScript.latestRun`); an action with no versions shows "Not run yet". Use cases have no icon. |
| `ScriptRunStatusIcon.tsx` | Whether a script version works, judged by its most recent run (`findScriptRunStatus`): a green check (`CheckCircle`, success color) when it passed, a red X (`Cancel`, error color) when it failed, a yellow exclamation (`Error`, MUI `amber[400]` - the theme's warning color is orange in dark mode) when it has no runs. Its accessible name and hover title are "Latest run passed", "Latest run failed", or "Not run yet" (`describeScriptRunStatus`). |
| `ScreenshotRunsSection.tsx` | The "Screenshots" section of a website's page: a line explaining when screenshots are taken (the website's timing settings), progress while a screenshot is being taken, the selected run (newest by default), and the "Run history" list to pick a run from. |
| `ScreenshotRunDetails.tsx` | One screenshot run in full: a `role="status"` outcome line ("Failed · HTTP 404 · 1.2 s") with its reason, when and where it was taken, and its image (or "No screenshot was captured"). |
| `WebsiteItemSummary.tsx` | The top of a use case's or action's page: kind, title with Edit (link) and Delete, description, an optional `detailText` line (an action's "Runs as: ..."), timestamps, and the delete dialog. The delete flow comes in as a `WebsiteItemDeletion` prop (`../hooks/useWebsiteItemDeletion.ts`). |
| `ActionScriptsSection.tsx` | The "Scripts" section of an action's page: the Model / Effort dropdowns (`ScriptModelPicker`) and the "Convert to script" button (Claude writes a JSON step plan) with progress and its error, a "Compare versions" link once there are two, the "Versions" list ("Version N", newest first, each with its `ScriptRunStatusIcon` from its `latestRun`, with model and effort - or "Refined from Version K · <model and effort>", or "Edited from Version K" - and an "Out of date" chip), and the selected version via `ActionScriptDetails`, keyed by its id. It works out the source version's number for edited and refined versions alike (`editedFromVersionNumber`, `refinedFromVersionNumber`). |
| `ActionScriptDetails.tsx` | One plan version in full: generated when and by which model at which effort (or refined from which version by which model, or edited from which version - checked edited, then refined, then generated), and who it logs in as; an "Out of date" warning when the action's title, description, or credential changed since; for a refined version, a "Refined from" block (the source version, the failed run's outcome and error - read from the run - the user's note, what Claude was sent: the screenshot when `screenshotWasSent`, the failing page snapshot when the run has one, and the tokens used: input, read from cache, written to cache, output); the title and description it was generated from; the summary and assumptions; the steps (`ActionPlanSteps`) with an "Edit steps" button that swaps in `ActionPlanEditor`; the "Pages given to Claude"; and the plan JSON. |
| `ActionPlanSteps.tsx` | A plan read-only: "Starts at <url>", then the steps as a numbered list of sentences (`describePlanStep`); credential placeholders are named, never shown. |
| `ActionPlanEditor.tsx` | The step editor: plan name and start URL, then the steps as cards in a dnd-kit `SortableContext` (drag a handle with the mouse or the keyboard - Space, arrows, Space), "Add step", a "Fix these before saving" list (`findPlanProblems`), and "Save as new version" (disabled until something changed and nothing is wrong) / Cancel. Steps get client-only ids for keys and dragging. |
| `ActionPlanStepFields.tsx` | One step card in the editor: drag handle, "Step N", the Action select, "Find element by" (role + name, label, placeholder, text, alt text, title, or CSS - plus "No element" for an optional target), the value field shaped by the action (key list, accept/dismiss, or text), and Move up / Move down / Delete. Only the fields the action takes are shown. |
| `ScriptModelPicker.tsx` | The "Model" and "Effort" dropdowns: every model in the live list, the chosen model's own effort levels (or a disabled "Standard"), and helper text naming the model id and its fallback. Shows why the list could not load instead. |
| `SideBySideDiff.tsx` | One section of a side-by-side comparison (older text left, newer right): removed lines red, added lines green, changed words highlighted, filler keeping rows aligned, "No differences" when equal. Rows come from `../utils/buildSideBySideDiff.ts`. |
| `ActionScriptRunsSection.tsx` | "Runs of version N": the "Run script" button (it opens a browser window on this computer, logging in as the action's credential first when it has one) with progress and its error, the selected run via `ActionScriptRunDetails` (keyed by the run's id, so the refine note and error start over per run), and the "Run history" list. Passes the refine state and `onRefine` through to the run details; Refine is disabled while a run is in flight. |
| `ActionScriptRunDetails.tsx` | One plan run in full: a `role="status"` outcome line ("Failed at step 3 · 4.2 s") with the error message, when it ran and who it was logged in as, "Failing page: <url>" when the run captured one, its step log, and its failure screenshot when there is one. A run with an error whose version Claude wrote (`versionCanBeRefined`) also gets the Refine area: a "Note for Claude (optional)" field (at most `MAX_REFINE_NOTE_LENGTH`, 2000 characters; sent trimmed, blank as null), the "Refine" button ("Refining…", with progress and "This can take a few minutes."), and "Could not refine: …" - shown only once this run's details tried to refine, like the step editor's save error. `onRefine` is called with the run and the note. |
| `CodeBlock.tsx` | A read-only, monospace, scrollable `<pre>` for code or program output, with an accessible name. Also shows aria snapshots. |
| `CrawlRunsSection.tsx` | The "Crawls" section of a website's page: what a crawl does (links, plus buttons when picked; up to 50 pages or 10 minutes; a credential logs in first), the "Crawl as" picker (logged out, or one of the website's credentials - `CRAWL_LOGGED_OUT_VALUE` is the logged-out option; shown only when `crawlAsPickerIsShown`), the "Buttons" picker ("Links only (no buttons)" = `DEFAULT_CRAWL_BUTTON_MODE`, "Buttons, except risky ones", "Only “Open” buttons"), the "Crawl website" button (disabled while starting one or while one is running) and its error, and the "Crawl history" list, each run saying who it crawled as (and which buttons it clicked, when not links only) and linking to its page. No `role="status"` region - a run's outcome is on its own page. |
| `CrawlSiteMap.tsx` | The "Site map" of a crawl: every page as one indented list in tree order (each page under the page whose link first led to it), with its path (a redirect shows as "/calendar (from /)" or "/old → /new", see `describeCrawledPagePath`), HTTP outcome, title, and " · via “Open Yoga”" when a button click led to it; picking a row selects the page. Built with `../utils/buildCrawlSiteTree.ts`. |
| `CrawledPageDetails.tsx` | One crawled page in full: path (with its redirect), outcome and duration, error, the URL loaded and where it ended up, title, the page it was found on (a button; ", by clicking “Open Yoga”" when a button click led here), the aria snapshot in a `CodeBlock`, its same-site links, and the "Pages its buttons led to" (both lists via the internal `CrawledUrlList`: visited ones select their page, the rest are marked "not visited"). |

## Conventions

- One default-exported component per file, with an exported `<Name>Props`
  interface whose fields are documented. Props arrive as a single `props`
  parameter and are destructured in the body.
- Forms own only their field values. Saving, error text, and navigation come
  from the page via props (`onSubmit`, `errorMessage`, `onCancel`).
- Forms seed their fields from `initialValues` once, on mount. Pages that edit
  a loaded record mount the form only after it loads, with `key={record.id}`.
- Submit stays disabled until the required fields are non-blank; the server
  still validates and its message is shown in an alert.
